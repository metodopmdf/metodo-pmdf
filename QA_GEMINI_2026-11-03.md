## Pendência bloqueadora: IA REAL ainda não ativada
O workflow `Publicar Gemini no Supabase (se configurado)` identificou que `SUPABASE_ACCESS_TOKEN` **não está configurado nos segredos do repositório**, portanto o passo de implantação da Edge Function foi ignorado.

Não é possível, com as permissões de GitHub disponíveis nesta conversa, criar um segredo privado no Supabase, aplicar SQL no banco do usuário ou validar uma chamada real ao Gemini.

**Antes de declarar o Gemini operacional para candidatos**, o administrador deve:
1. Executar a migração de cotas no SQL Editor Supabase;
2. Armazenar `GEMINI_API_KEY` e `GEMINI_ENABLED=true` no Supabase;
3. Implantar a Edge Function com `SUPABASE_ACCESS_TOKEN` via GitHub Actions ou CLI;
4. Testar uma conta real de QA. O repositório inclui `tests/gemini-live.mjs`, que é executado apenas se os segredos `PMDF_GEMINI_QA_USER` e `PMDF_GEMINI_QA_PASSWORD` forem configurados.

**Não declarar sucesso do Gemini REAL** até que o teste 4 passe. A interface mostra que o backend não está pronto quando a Edge Function ainda não está implantada.

## Limites e segurança
- A validação de citação literal e estrutura não equivale a uma auditoria humana do gabarito jurídico; conferência na fonte vigente continua necessária.
- O Google pode aplicar cotas ou cobrança conforme configuração, modalidade gratuita e modelo. Limites diários internos não garantem ausência de custo quando o projeto tem faturamento habilitado.
- Trechos de leis/documentos enviados à opção Gemini são processados pelo Google por meio do Supabase; o modo seguro não transmite o conteúdo ao Google.
- Meta de 100/200 questões é progressiva e dependente da suficiência da fonte e da capacidade do modelo; não representa garantia de quantidade ou qualidade semântica.
